# UXF-014: the screen-only user reads link names without word breaks

- id: UXF-014
- title: The screen-only user joins the words of a link whose parts are separate blocks, and then cannot find the link by name
- class: engine
- severity: S1
- metric: screen_only.incomplete
- status: closed
- found_by: R-02 round command on the ess site (find-install-command, keyboard, 1366x768 light)
- evidence_recording: none (no recordings in R-02)
- evidence_screenshot: ux/rounds/R-02/shots/sites/ess/worst-1.png
- evidence_lines: ux/rounds/R-02/report.md, "Per site", ess: `link "NextInstall ess" on screen has a different accessible name`
- regression_asset: tests/ux-checks.browser.mjs check UXF-014

The bot takes a link's name from `textContent`, which joins block children without a space: the
Docusaurus pagination link (`<div>Next</div><div>Install ess</div>`) became "NextInstall ess", while
the browser's accessible name is "Next Install ess". The bot then reported a different accessible
name and failed gate 5 (keyboard only) at a gating viewport although a real keyboard reader reaches
and names the link.

Severity S1: it fails a hard gate at a gating viewport.

Fix: the bot reads the rendered text (`innerText`), so block children are separate words. Red on the
R-01 tool (fixture link `<div>Next</div><div>Install tool</div>`), green after.

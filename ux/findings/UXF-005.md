# UXF-005: the product-site template ships no search

- id: UXF-005

- metric: layout.optional_missing
- status: open, waiting on ux/rounds/R-01/decision.md
- found_by: R-01 round command, always-visible check
- evidence_recording: none (no recordings in R-01)
- evidence_screenshot: ux/rounds/R-01/shots/contact-sheet-light.png (navbar in every frame)
- evidence_lines: ux/rounds/R-01/report.md, "Per viewport", search absent column (12 of 12 pages, every view)
- regression_asset: none yet; on a yes, the adapter's search entry becomes required and gate 2 holds it

The adapter lists search as an always-visible element for a docs site. `withProductSite` adds no
search to the navbar and the example site has none, so a reader who knows a word but not the page has
only the navigation. The screen-only user completes all three cards by navigation, so this does not
fail a gate today; it is reported on every view.

Adding a search is a product decision (a dependency and an index step in every consuming build); it
is asked in `ux/rounds/R-01/decision.md`.

# UXF-012: the always-visible check reports a scrolling sidebar as outside the viewport

- id: UXF-012
- title: The always-visible check reports a docs sidebar that scrolls inside its own column as outside the viewport
- class: engine
- severity: S1
- metric: layout.hidden
- status: closed
- found_by: R-02 round command on the ess, inference and llm sites
- evidence_recording: none (no recordings in R-02)
- evidence_screenshot: ux/rounds/R-02/shots/sites/ess/worst-1.png
- evidence_lines: ux/rounds/R-02/report.md, "Per site"; ess 15 and inference 104 gate failures at 1366x768 and 1280x720, all `sidebar: 12,94..278,893 outside 1366x768`
- regression_asset: tests/ux-checks.browser.mjs check UXF-012

The adapter checks the sidebar menu element (`.theme-doc-sidebar-menu`) against the viewport. On a
site with a long sidebar the menu is taller than the screen, and Docusaurus scrolls it inside the
sticky sidebar column (`overflow-y: auto`), so the column is fully in view and every item is
reachable. The check measured the menu, not the column, and failed gate 2 on every docs page of any
site with a long or expanded sidebar (ess, inference, llm: 119 gating failures, 260 checks over all
viewports on inference alone). Nothing was wrong on the page; the gate would have blocked every merge
on those sites.

Severity S1: a hard gate that fails at both gating viewports with no page defect behind it.

Fix: when the checked element sits inside an ancestor that scrolls vertically (`overflow-y` auto or
scroll, content taller than the box), that ancestor's box is what must be in the viewport and
uncovered. A sidebar with no scrolling column that runs past the screen still fails. Red on the R-01
tool (fixture: 60 items, sticky column), green after; a second fixture without a scrolling column
keeps the check able to fail.

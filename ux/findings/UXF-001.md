# UXF-001: a graph node's accessible name leaves out the kicker it shows

- id: UXF-001
- title: A graph node's accessible name leaves out the kicker it shows
- class: affordance
- severity: S1
- metric: axe.serious_critical (label-content-name-mismatch)
- status: closed
- found_by: R-01 round command, axe-core
- evidence_recording: none (no recordings in R-01)
- evidence_screenshot: ux/rounds/R-01/shots/worst-1.png
- evidence_lines: ux/rounds/R-01/report.md, "Worst moments" and "Failing checks"
- regression_asset: tests/product-site.browser.mjs check UXF-001

Every protocol and domain graph node (`role="button"`) shows a kicker such as `ACTION · WRITE` or
`EVIDENCE KIND` above its name, and its `aria-label` (`Action repository.edit. …`) does not contain
that text. A voice-control user who says what they see ("click action write") reaches nothing
(WCAG 2.5.3, Label in Name). Seen on 5 of 12 pages (landing, art, charts, reference, heroes) in
every viewport and theme.

Severity S1: it fails hard gate 5 at both gating viewports, so no merge can pass with it.

Fix: the accessible name starts with the node's visible text in reading order: `Action · Write
repository.edit. …` for a protocol node, `Entity · 2 fields Agent Registered. …` for a domain node
(kicker, name, the lifecycle chips it shows). The SVG texts end in a space so that axe-core, which
joins them without one, reads separate words. Red on the R-01 build, green after.

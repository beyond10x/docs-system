# UXF-011: a keyboard reader needs up to 36 key presses for a two-click task

- id: UXF-011
- title: A keyboard reader needs up to 36 key presses for a two-click task
- class: affordance
- severity: S3
- metric: screen_only.keyboard_actions
- status: open, needs a design decision (queued after R-01's decision)
- found_by: R-01 report reviewer (review-report.md § 2 item 2), confirmed by the fixed screen-only user
- evidence_recording: none (no recordings in R-01)
- evidence_screenshot: ux/rounds/R-01/shots/review-keyboard-focus-1024-light.png
- evidence_lines: ux/rounds/R-01/triage.md, "Measured again with the fixed tools"; ux/rounds/R-01/review-report.md § 2 item 2
- regression_asset: none yet; the ratchet holds screen_only.keyboard_actions per card and viewport

With Tab presses counted, `find-adopt-config` costs 36 key presses at 1024x768 (13 Tab presses to the
hero button, then 21 more through the navbar to "Adopt the template" in the sidebar) against 2 clicks.
At 390x844 the tasks cost 18 to 23 presses. Every keyboard run is affected (15 of 15). The skip link
jumps to the content, not to the docs navigation.

Fix (needs a yes/no, an interaction change): a second skip link to the docs navigation, or the
sidebar before the navbar's right-hand items in the tab order.
